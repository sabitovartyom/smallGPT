01 / ГРАНИЦЫ MVP

Одна задача, полный цикл

Модель получает начало истории и продолжает текст. Например: Once upon a time there was a little fox. Успех — рабочее обучение, снижение ошибки на новых историях и генерация, постепенно осваивающая язык и стиль корпуса.

Обучение на продолжение текста само по себе не учит выполнять инструкции или вести диалог. Для этого впоследствии потребуется соответствующий формат данных и отдельный этап обучения.

03 / ПРЕДСТАВЛЕНИЕ ТЕКСТА

Tokenizer и embeddings

Tokenizer: текст превращается в индексы

Токен — символ, часть слова или целое слово, в зависимости от токенизатора. Tokenizer задаёт обратимое преобразование encode(text) → IDs и decode(IDs) → text. Это отдельный компонент; его правила не обучаются через backward языковой модели.

  • Для первого smoke test: посимвольный словарь на маленьком корпусе. Реализуется через два словаря Python; для неизвестных символов нужна явная политика.
  • Для основного запуска: byte-level BPE примерно на 4096 токенов. Начинает с байтов, затем учит слияния частых соседних единиц. Его можно реализовать отдельно или обучить библиотекой Tokenizers.
  • Специальный токен: EOS завершает историю. PAD нужен, только если используешь padding; при packing одинаковых окон можно обойтись без него.

Раздели истории на train и validation до нарезки на окна. Токенизатор обучай только на train. Добавь EOS между историями, собери последовательность IDs и выбирай окна длиной T+1. При таком простом packing истории разделены EOS, но attention между ними не блокируется.

TokenEmbedding: смысловое представление

Обучаемая таблица [V, D]. По ID выбирается строка из D чисел. Для максимальной прозрачности это просто weight[token_ids]; nn.Embedding делает такое же извлечение с поддержкой autograd.

PositionEmbedding: порядок в последовательности

Обучаемая таблица [T_max, D]. Векторы позиций 0…T−1 складываются с векторами токенов. Attention без позиционной информации не задаёт сам по себе полное представление порядка токенов.

# token_ids: [B, T], dtype=torch.long
B, T = token_ids.shape
assert T <= context_length
positions = torch.arange(T, device=token_ids.device)
x = token_embedding(token_ids) + position_embedding(positions)
# [B, T, D] + [T, D] через broadcasting → [B, T, D]
04 / СВЯЗИ МЕЖДУ ТОКЕНАМИ

Causal multi-head self-attention

Attention позволяет позиции собрать информацию из доступных токенов. Каждая голова рассчитывает собственные веса связей; это даёт несколько параллельных способов смешивать информацию.

Q, K и V

Query текущей позиции сравнивается с Keys всех доступных позиций. После softmax полученные коэффициенты используются для взвешенной суммы Values.

Это обучаемые проекции hidden states; конкретные роли голов заранее не задаются.

Масштабирование

Скалярные произведения делятся на √d_head. Это сдерживает рост их масштаба при увеличении размерности головы и помогает избежать слишком резкого softmax.

scores = Q @ K.transpose(-2, -1) / sqrt(d_head)
weights = softmax(scores + causal_mask, dim=-1)
output = weights @ V
ШагРазмер тензора
Вход x[B, T, D]
Общая проекция QKV[B, T, 3D]
Q, K, V после разбиения на головыКаждый [B, H, T, d_head], где D = H × d_head
Scores и weights[B, H, T, T]; последняя ось — позиции keys
Взвешенные Values[B, H, T, d_head]
Объединение голов и выходная проекция[B, T, D]

Causal mask: позиция видит только прошлое и себя

Строка матрицы соответствует query, столбец — key. Верхний треугольник получает -inf до softmax, поэтому вероятность внимания к будущему равна нулю.

Каркас ручной реализации attention

Для первого варианта без dropout и KV-cache. Все Linear используют bias. Маска — boolean buffer размера T_max × T_max, зарегистрированный в модуле.

import math
import torch
from torch import nn

class CausalSelfAttention(nn.Module):
    def __init__(self, d_model, n_heads, context_length):
        super().__init__()
        assert d_model % n_heads == 0
        self.n_heads = n_heads
        self.head_dim = d_model // n_heads
        self.qkv = nn.Linear(d_model, 3 * d_model)
        self.proj = nn.Linear(d_model, d_model)
        mask = torch.ones(context_length, context_length,
                          dtype=torch.bool).tril()
        self.register_buffer("causal_mask", mask, persistent=False)

    def forward(self, x):
        B, T, D = x.shape
        assert T <= self.causal_mask.size(0)
        q, k, v = self.qkv(x).chunk(3, dim=-1)

        def split_heads(t):
            return t.reshape(B, T, self.n_heads,
                             self.head_dim).transpose(1, 2)

        q, k, v = map(split_heads, (q, k, v))
        scores = (q @ k.transpose(-2, -1)) / math.sqrt(self.head_dim)
        scores = scores.masked_fill(
            ~self.causal_mask[:T, :T], float("-inf")
        )
        weights = torch.softmax(scores, dim=-1)
        y = weights @ v
        y = y.transpose(1, 2).contiguous().view(B, T, D)
        return self.proj(y)

При первом запуске в FP32 этот код удобно отлаживать. Для mixed precision учитывай численную устойчивость scores и softmax. Позже сравни ручную реализацию с F.scaled_dot_product_attention(..., is_causal=True) при отключённом dropout.

05 / ОСНОВНОЙ ПОВТОРЯЮЩИЙСЯ БЛОК

LayerNorm → Attention → FFN

Блок сохраняет размер [B, T, D]. Attention смешивает информацию между позициями; FFN применяет нелинейное преобразование независимо к каждой позиции, используя общие веса.

x = x + attention(norm1(x))
x = x + ffn(norm2(x))

LayerNorm

Среднее и дисперсия вычисляются по последней оси D отдельно для каждой позиции и каждого примера. Нормализация не смешивает токены или элементы батча. Затем применяются обучаемые масштаб γ и сдвиг β, оба размера [D].

μ = mean(x, dim=-1, keepdim=True)
σ² = mean((x − μ)², dim=-1, keepdim=True)
LN(x) = γ · (x − μ) / sqrt(σ² + ε) + β

При реализации через torch.var используй correction=0, чтобы соответствовать формуле выше. Начальные γ = 1, β = 0; ε, например, 1e-5.

Residual connection

Результат каждой ветки добавляется к её входу. Так блок учит поправку к текущему представлению, а градиент получает прямой путь через сложение. Для сложения размерность выхода ветки должна совпадать с размерностью x.

Feed-forward network

Первая проекция расширяет D до 4D, GELU добавляет нелинейность, вторая возвращает размер D. В базовом варианте это 384 → 1536 → 384.

ffn = nn.Sequential(
    nn.Linear(d_model, 4 * d_model),
    nn.GELU(),
    nn.Linear(4 * d_model, d_model),
)

Почему pre-norm: нормализуем вход каждой ветки до её преобразования. Это удобный старт для обучения Transformer. После всех L блоков добавляем ещё одну LayerNorm перед LM head.

Что действительно писать вручную

Собери свои CausalSelfAttention, FeedForward, TransformerBlock и TinyLM. Для дополнительной практики — собственные LayerNorm и Embedding.

Автоматическое дифференцирование, матричные операции, nn.Linear, F.cross_entropy и torch.optim.AdamW можно оставить PyTorch. Готовые nn.Transformer и nn.MultiheadAttention здесь не нужны.

06 / ЦЕЛЬ ОБУЧЕНИЯ

Logits → следующий токен

LM head проецирует hidden state каждой позиции из D в V. Logits — произвольные оценки для токенов словаря; это ещё не вероятности. Для loss передавай их непосредственно в cross-entropy: она уже включает log-softmax.

Weight tying

Таблица embedding имеет размер [V, D], как и вес Linear(D, V). Можно использовать один и тот же Parameter: входные и выходные представления тогда учатся совместно, а число параметров уменьшается на V·D.

self.lm_head = nn.Linear(d_model, vocab_size, bias=False)
self.lm_head.weight = self.token_embedding.weight
# Назначение выполняется в __init__, до создания optimizer.

Сдвиг target на одну позицию

Исходное окно: [A, B, C, D, EOS]
Вход x: [A, B, C, D]
Target y: [B, C, D, EOS]

Logits на позиции A должны предсказать B; logits на позиции B — C. Target получается из реальных данных, а модель благодаря маске не видит будущие токены.

# batch_tokens: [B, T+1]
x = batch_tokens[:, :-1]
y = batch_tokens[:, 1:]
logits = model(x)                       # [B, T, V]
loss = torch.nn.functional.cross_entropy(
    logits.reshape(-1, vocab_size),
    y.reshape(-1),
)

При padding исключи PAD-позиции из loss через ignore_index и корректно учитывай padding в attention. Для первого MVP проще использовать окна одинаковой длины без padding.

07 / ПРАКТИЧЕСКИЙ TRAINING LOOP

Сначала доказать, что модель учится

Начни с маленькой версии: 2 блока, D=128, 4 головы, контекст 64 и посимвольный tokenizer. Переобучи один фиксированный батч. Это быстрый способ обнаружить ошибки в маске, targets и gradient flow до большого запуска.

Основной корпус

TinyStories содержит синтетические короткие англоязычные истории с простым словарём. Для первого эксперимента можно выбрать подмножество примерно на 10–30 млн токенов после BPE. Это ориентир для масштаба эксперимента, а не гарантия связной генерации.

Отложи отдельные истории для validation, убери точные дубликаты между split. Сохрани tokenizer и уже токенизированные данные, чтобы повторные запуски использовали одинаковое представление.

НастройкаСтартовый выбор
OptimizerAdamW, LR 3e-4, betas (0.9, 0.95), weight decay 0.01.
Decay-группыDecay для матриц весов; bias и параметры LayerNorm — без decay. Общий embedding/head Parameter включается один раз.
SchedulerWarmup первые ~5% updates, затем cosine decay до 10% исходного LR.
Gradient clippingМаксимальная норма 1.0 после backward, до optimizer.step.
BatchНачать с 4–8 окон по 256 токенов, затем подобрать по памяти. При необходимости добавить accumulation.
ТочностьFP32 для отладки; затем BF16 autocast, если оборудование поддерживает. FP16 требует подходящего GradScaler.
ValidationЧерез фиксированное число optimizer updates; model.eval() и inference_mode().

Гиперпараметры выше — исходная точка. Скорость и время обучения зависят от GPU, длины контекста и реализации attention; их стоит измерить на коротком запуске.

Минимальный шаг обучения в FP32 
model.train()
optimizer.zero_grad(set_to_none=True)
logits = model(x)
loss = torch.nn.functional.cross_entropy(
    logits.reshape(-1, vocab_size), y.reshape(-1)
)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
optimizer.step()
# Если scheduler настроен на optimizer updates:
scheduler.step()

Что сохранять и смотреть

  • Train и validation loss. Рост разрыва между ними помогает заметить переобучение. Perplexity = exp(loss), если loss измерен натуральным логарифмом; сравнивай её при одинаковой токенизации и выборке.
  • Tokens/sec и обработанные токены. Количество updates без размера батча и контекста плохо описывает объём обучения.
  • Фиксированные prompts. Сохраняй генерации с одинаковыми sampling-настройками через равные интервалы обучения.
  • Checkpoint. Веса, optimizer, scheduler, step, конфигурация и tokenizer. Для точного возобновления также нужны RNG states, положение sampler и GradScaler при FP16.

При gradient accumulation дели loss на число microbatches. Clipping, optimizer.step(), scheduler.step() и zero_grad() выполняются один раз на полный накопленный update.

08 / АВТОРЕГРЕССИВНОЕ ПРОДОЛЖЕНИЕ

Один новый токен за шаг

  1. Закодируй непустой prompt и вызови модель для его token IDs.
  2. Возьми logits[:, -1, :] — предсказание после последней позиции.
  3. Раздели logits на положительную temperature, при необходимости оставь top-k.
  4. Примени softmax, выбери токен через multinomial и добавь его к входу.
  5. Повторяй до EOS или max_new_tokens. Decode выполняется тем же tokenizer.

Temperature ниже 1 обычно делает выбор более концентрированным; выше 1 — более разнообразным. Top-k ограничивает sampling k наиболее высокими logits. Для отдельного детерминированного режима используй argmax.

Каркас генерации для одного prompt

Предполагает batch size 1, непустой вход и положительную temperature. Здесь нет KV-cache: весь текущий контекст пересчитывается на каждом шаге.

@torch.inference_mode()
def generate(model, ids, context_length, eos_id,
             max_new_tokens=100, temperature=0.8, top_k=40):
    assert ids.ndim == 2 and ids.size(0) == 1 and ids.size(1) > 0
    assert temperature > 0 and top_k > 0
    model.eval()
    for _ in range(max_new_tokens):
        x = ids[:, -context_length:]
        logits = model(x)[:, -1, :] / temperature
        k = min(top_k, logits.size(-1))
        values, indices = torch.topk(logits, k, dim=-1)
        filtered = torch.full_like(logits, float("-inf"))
        filtered.scatter_(-1, indices, values)
        probs = torch.softmax(filtered, dim=-1)
        next_id = torch.multinomial(probs, num_samples=1)
        ids = torch.cat((ids, next_id), dim=1)
        if next_id.item() == eos_id:
            break
    return ids

При превышении T_max этот вариант берёт последние T_max токенов и заново нумерует позиции с нуля. Это простая стратегия для MVP; она теряет ранний контекст и меняет абсолютные позиции. При обучении на случайных окнах такое поведение естественно, но длинная история может терять связность.

Критерии готовности

  • Будущие токены не влияют на logits более ранних позиций: меняем суффикс входа при model.eval() и сравниваем logits общего префикса.
  • LayerNorm совпадает с nn.LayerNorm при одинаковых параметрах и ε; attention близок к SDPA при dropout=0.
  • Модель переобучается на одном батче; loss и gradients конечны.
  • Validation использует отдельные истории и не обновляет веса.
  • Сохранённая и загруженная модель даёт одинаковые logits в eval; обучение возобновляется с состояниями optimizer и scheduler.
  • Генератор работает с коротким и длинным prompt, соблюдает EOS и max_new_tokens.

Следующие эксперименты — по одному изменению

После базовой модели попробуй learned positions → RoPE, LayerNorm → RMSNorm, GELU FFN → SwiGLU. KV-cache ускоряет генерацию, а SDPA — attention. Для архитектурных сравнений сохраняй tokenizer, данные и бюджет обработанных токенов; учитывай число параметров при изменении FFN.
