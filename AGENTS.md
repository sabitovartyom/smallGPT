# smallGPT — контекст и инструкции для агента

## Цель проекта

Учебный пет-проект: написать маленькую GPT-подобную языковую модель на
PyTorch и обучить её с нуля на небольшом корпусе. Основная цель — разобраться
в архитектуре, обучении и генерации, реализуя большую часть компонентов вручную.

Общайся с пользователем на русском. Объясняй назначение блоков, размеры
тензоров и причины существенных решений. Не реализуй весь проект заранее:
выбирай объём работы по текущему запросу пользователя, оставляя ему возможность
писать и изучать компоненты самостоятельно.

## Предпочтения пользователя

Большую часть архитектуры пользователь хочет написать именно вручную на torch.

- Реализуй attention через Q/K/V, матричные произведения, разбиение на головы,
  causal mask и softmax; явно показывай движение размерностей.
- Собери собственные FeedForward, TransformerBlock и модель целиком.
- Не подменяй это готовыми `nn.Transformer`, `nn.MultiheadAttention` или
  pretrained-моделью из Transformers, если пользователь не попросил иначе.
- `nn.Linear`, `nn.Embedding`, autograd, `F.cross_entropy` и AdamW допустимы.
- Собственная LayerNorm и tokenizer — полезные учебные компоненты, но пока
  не обязательное требование. Библиотечный BPE тоже допустим.
- Сначала обеспечь понятный рабочий baseline; добавляй оптимизации и новые
  архитектурные варианты по одному, когда для них есть запрос или необходимость.

## Предложенный MVP, пока не жёсткое техническое задание

Пользователь запросил предложение MVP и документацию; следующие настройки
были предложены агентом, но не являются обязательными решениями пользователя.

Задача: продолжать короткие истории по началу текста. Обучение — next-token
prediction. Чат, instruction tuning и выполнение команд пока не входят в MVP.

Базовая архитектура:

| Параметр | Предложение |
| --- | --- |
| Тип | Decoder-only Transformer |
| Блоки | 6 |
| Hidden size | 384 |
| Attention heads | 6, head dimension 64 |
| Максимальный контекст | 256 токенов |
| FFN | 384 → 1536 → 384, GELU |
| Нормализация | Pre-norm LayerNorm и финальная LayerNorm |
| Позиции | Learned positional embeddings |
| Tokenizer | BPE, примерно 4096 токенов |
| LM head | Linear без bias, общий Parameter с token embedding |
| Размер | 12 318 720 параметров при Linear с bias и affine LayerNorm |

Путь данных:

```text
token IDs [B,T]
  → token embedding + position embedding [B,T,D]
  → L × TransformerBlock [B,T,D]
  → final LayerNorm [B,T,D]
  → LM head [B,T,V]
```

Блок:

```python
x = x + attention(norm1(x))
x = x + ffn(norm2(x))
```

Предложенные данные: английский TinyStories, сначала подмножество примерно
на 10–30 млн токенов после токенизации. Это масштаб первого эксперимента,
а не обещание качества. Русский корпус пока не обсуждался. Оборудование,
бюджет обучения и зависимости проекта пока не определены.

Для быстрой отладки предложены 2 блока, D=128, 4 головы, контекст 64 и
посимвольный tokenizer. После проверки pipeline можно перейти к основной модели.

## Порядок работ и проверки

1. Tokenizer, разделение историй на train/validation, окна входов и targets.
2. Ручной causal attention с проверкой размерностей и маски.
3. FFN, нормализации, residual connections, embeddings и LM head.
4. Training loop и переобучение одного фиксированного батча без dropout.
5. Основной корпус, validation, сохранение и восстановление checkpoint.
6. Генерация с temperature, top-k, EOS и max_new_tokens.

Существенные условия корректности:

- Разделяй данные по историям до нарезки окон. Tokenizer обучай только на train.
- Targets сдвинуты на один токен; cross-entropy получает сырые logits.
- Causal mask допускает текущую позицию и прошлое. Изменение суффикса входа
  не должно менять logits общего префикса в eval.
- D делится на число голов. LayerNorm нормализует последнюю ось D;
  при ручной реализации дисперсия вычисляется с `correction=0`.
- Общие embedding/head weights — один Parameter; optimizer не должен учитывать
  его дважды. Назначай общие веса до создания optimizer.
- Validation и генерация работают в eval без градиентов.
- Checkpoint содержит конфигурацию, tokenizer, модель, optimizer, scheduler
  и update step; для точного возобновления нужны также RNG и sampler states.
- После сохранения/загрузки logits в eval совпадают; gradients и loss конечны.

AdamW с LR 3e-4, warmup/cosine decay и gradient clipping 1.0 предложены как
стартовые настройки, а не фиксированные требования. Batch size и точность
подбирай под доступное оборудование. Не обещай время обучения без измерений.

## Возможная структура проекта

Пока это предложение, а не список файлов, которые нужно немедленно создать:

```text
config.py       # размеры модели и настройки обучения
tokenizer.py    # encode/decode, обучение и сохранение tokenizer
data.py         # split, packing, token windows
model.py        # attention, FFN, block, TinyLM
train.py        # training loop, validation, checkpoint
generate.py     # загрузка модели и sampling
checks.py       # точечные проверки корректности
```

RoPE, RMSNorm, SwiGLU, KV-cache и SDPA оставлены для последующих экспериментов.
Этот файл передаёт контекст следующему агенту; последующие инструкции
пользователя имеют приоритет над описанными предложениями.
